# 多技能投资策略专家包（expert-package）

> **本仓库投资域的默认核心。** 无固定人格、无角色扮演——以"技能库 + 情景路由 + 策略输出协议"工作：
> 识别情景 → 组合调用技能模块 → 输出可执行、可验证、可迭代的策略方案。
> 主提示词：`SKILL.md`（含 frontmatter，可直接安装为技能）；模块展开：`modules/`。

---

## 一、结构与加载方式

```
expert-package/
├── SKILL.md                     ★ 主提示词（安装为技能 / 作为 System Prompt 常驻）
├── modules/
│   ├── 01-量化策略.md           因子/回测/过拟合/成本/组合/监控
│   ├── 02-股票研究.md           七问/五维/估值工具箱/证伪条件
│   ├── 03-ETF策略.md            选品清单/四类策略/条件化规则
│   ├── 04-资产配置.md           约束补全/四方法/量化骨架/压力测试
│   ├── 05-风险管理.md           事前约束/四类止损/尾部风险/失效退出
│   ├── 06-交易执行.md           订单/分批/滑点/纪律/复盘
│   ├── 07-宏观与市场.md         核心变量/周期象限/四把温度计
│   ├── 08-合规与风险揭示.md     硬约束/信息分层标注/免责声明（全场景默认层）
│   └── 09-情景路由示例.md       十个典型场景的完整路由与输出骨架
└── README.md                    ← 本文件
```

**渐进式加载**（成本与质量的最佳平衡点）：
1. 常驻：`SKILL.md` 全文（轻量，含路由规则）；
2. 按需：命中情景后加载对应 `modules/` 文件（1–3 个，避免堆砌）；
3. 工具：需要取数/回测/渲染时按 SKILL.md 附录 A 调用 `../skills/` 与 `../../quant-tools/`。

## 二、各环境安装

| 环境 | 方式 |
|---|---|
| WorkBuddy | 在专家中心/技能管理导入本目录（SKILL.md 为入口）；或直接粘贴 SKILL.md 到系统提示 |
| Claude Code / Cursor 等 | 目录拷入 `~/.claude/skills/` 等技能目录（保持 modules/ 相对结构） |
| 网页版（Claude/ChatGPT） | 粘贴 SKILL.md 全文作首条消息；需要某模块时把对应 modules/*.md 一并贴上 |
| 自研 Agent | SKILL.md 作系统提示；实现"技能目录表 → 模型声明需要 → 下一轮注入对应模块"的循环 |

## 三、与仓库其他部分的关系

| 资产 | 关系 |
|---|---|
| `workbenches/investment/`（工作台管家） | **分工**：管家管个人的日常执行（股债利差定投的简报/台账/复盘）；本专家包管广义策略问答。涉及个人动作建议 → 回到工作台固化规则复核 |
| `../skills/` | 本专家包的**工具层**（数据层/研报交付物/md-to-html/分发） |
| `../../quant-tools/` | 量化模块的**执行引擎**（复现/过拟合/tearsheet） |
| `../experts/` + `../workflows/` | **可选深度模式（默认不启用）**：多视角人格圆桌/大师漏斗/对抗辩论。仅在需要"多人格对抗"时启用；日常一律用本专家包 |

## 四、设计原则

1. **无固定人格**：以技能模块响应，不用"我是某分析师"的口吻；
2. **情景路由**：先判情景、再调模块；跨域问题组合调用；不明确先给 1–3 个情景判断；
3. **输出协议**：九段式模板（情景判断/目标约束/核心策略/执行规则/参数示例/验证方法/风险失效/备选方案/下一步）按复杂度裁剪；
4. **数字纪律**：不编数据、不承诺收益、事实/假设/判断分层标注；
5. **条件化表达**：不给"精确买卖点"，给"若 A 发生 → 执行 B + 风险说明"。
