# 模块 01 · 量化策略

> 触发情景：用户问"量化、因子、回测、信号、策略开发"。
> 模块目标：把"一个想法"变成"可验证、可复现、可迭代的量化策略资产"。
> 配套工具：`../../quant-tools/` 三件套（研报复现 / 过拟合检验 / 绩效 tearsheet）。

---

## 1. 研究流程（六步，每步有交付物）

```
① 假设 → ② 数据与标的池 → ③ 因子/信号构建 → ④ 回测与验证
→ ⑤ 组合与执行假设 → ⑥ 监控与迭代
```

## 2. 数据频率与标的池

| 检查项 | 要点 |
|---|---|
| 频率 | 日频（默认起步）/ 周频 / 分钟级（仅在有明确微观结构理由时）；频率决定成本假设与容量上限 |
| 标的池 | 明确 universe（全A？剔除 ST/新股/低流动性？）；**池子必须在回测全程按当时可得信息动态维护**（防幸存者偏差） |
| 数据窗口 | 样本起点说明理由；牛熊震荡至少各覆盖一段；数据来源、复权方式、缺失值处理逐项记录 |
| 时点纪律 | 财务数据按"实际可得日"对齐（A股公告滞后），严禁按报告期对齐 |

## 3. 因子/信号构建

- 预处理链：去极值（MAD/分位截断）→ 标准化（z-score/rank）→ 中性化（行业/市值，按需）；
- 有效性初筛指标：IC、Rank IC、ICIR、IC t 值、IC 为正比率（经验参考区间：|IC|>0.03、ICIR>0.3 值得进一步验证——非承诺，仅作筛选起点）；
- 信号转持仓：分层（quantile）/阈值/排序；调仓时点与信号生成时点之间**必须留执行延迟**（如 T 日收盘信号、T+1 开盘执行）。

## 4. 回测与验证（这一节决定策略生死）

| 检查项 | 要点 |
|---|---|
| 前视偏差 | 财务 lag、指数成分变动 lag、价格对齐（信号/执行价分离）逐项审计 |
| 样本外 | IS/OOS 切分 + walk-forward；OOS 必须"从未参与过任何选择" |
| 过拟合检验 | **DSR**（扣多重检验后 SR>0 概率）、**PBO**（样本内最优在样本外沦为中等的概率）、**Haircut**（Bonferroni/Holm/BHY 打折）、**MinTRL**（显著性所需最短样本）——用 `quant-tools/backtest-overfit` 出 OverfitReport；**诚实申报试验次数 n_trials（少报=自欺）** |
| 参数敏感性 | 参数邻域的绩效曲面必须平缓；尖峰=过拟合信号 |
| 基线对照 | 反向因子 / 固定种子随机因子（阴性对照）/ 等权买入持有 / 零收益基线 |
| 成本与滑点 | 双边费用+印花税+滑点（按流动性分档假设）；对高换手策略做**成本敏感性曲线**；给出容量估计（策略规模上限） |
| 结论口径 | 最终结论只能是：有效 / 弱有效 / 无效 / 依赖特定市场状态 / 不可判定（数据不足时明说） |

## 5. 组合、仓位与再平衡

- 优化目标：均值-方差 / 风险平价 / 等权（等权常是最稳的基线，先证伪等权再上复杂优化）；
- 约束：单标的权重上限、行业上限、换手率上限、杠杆=0（默认，如需杠杆必须单列风险说明）；
- 再平衡：定期（月/季）或阈值触发（偏离>X%）；注意再平衡本身产生成本与税负；
- 止损体系见 `05-风险管理.md`，执行细节见 `06-交易执行.md`。

## 6. 实盘监控与迭代

- 上线前：纸面交易或小资金验证 ≥1 个完整周期；记录实际滑点 vs 假设滑点的偏差；
- 监控仪表：滚动 IC、滚动夏普、回撤、换手执行率、信号-成交偏离；
- **失效判断**（触发任一条即停手复盘）：滚动 IC 连续 N 期为负且超出历史波动范围 / 回撤突破历史最大回撤的 1.2 倍 / 实际滑点长期 2 倍于假设 / 市场结构变化（规则、参与者、费率）使前提不成立；
- 迭代纪律：每次改动记录"改了什么、为什么、预期影响"，用同一验证框架重跑（`quant-tools/report-replication` 的六步+质量门可作流程参照）。
