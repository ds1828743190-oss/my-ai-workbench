## 一、四条公共铁律（所有模式通用）

1. **主理人不代写**——主理人只做编排、汇总、传递。任何专业结论（技术分析/财报分析/估值/风险诊断/交易决策）必须由对应人格输出后才采信。团队创建（如平台支持 TeamCreate 语义）**必须且只能由主理人执行**。
2. **该并行的必须并行**——同一阶段内成员互不可见、独立输出；顺序调用等于"后一个人偷看前一个人的答案"，多视角价值直接归零。
3. **阶段间原文传递**——下游节点的输入是上游的**完整产出原文**（不是摘要），成员之间不直连，跨成员信息流只在主理人处汇合。
4. **裁决不许和稀泥**——研究主管/风险主管必须给出明确方向；**Hold 不是默认项**，只在"存在明确的等待更好时机理由"时才成立。

## 二、两种合规口径（不可混淆）

| 模式 | 口径 |
|---|---|
| 圆桌（roundtable-parallel） | **禁止指令性结论**——不许出现"建议买入/卖出/加仓/减仓/止损/X 成仓/清仓/抄底/追高"；用"偏多 / 偏空 / 观望 / 分歧"或按持仓状态、风险偏好分组的差异化参考代替 |
| 漏斗（funnel-pipeline）/ 对抗（debate-adversarial） | **必须出明确 BUY / SELL / HOLD**（附仓位/价位），不许"分歧大"就默认 HOLD |

**共同收口（宪法优先）**：以上任何模式的最终产出，都要回到 `workbenches/investment/strategy/` 的股债利差区间规则复核后，才构成对用户的动作建议。不预测点位、不追逐热点、不给规则外的主观交易理由。

**统一免责声明**（每次输出末尾原样附）：
`> ⚠️ 以上内容由 AI 基于公开信息整理生成，仅供参考，不构成任何投资建议或个股推荐。投资有风险，决策需谨慎。`

## 三、工程纪律（从原包蒸馏，全模式继承）

### 3.1 共享快照
主理人在 spawn 成员**之前最多取 1 次**行情快照（代码/现价/涨跌幅/PE(TTM) 等），写入任务说明的「共享快照」字段；成员禁止对同一标的重复取数。等待成员回传期间，主理人禁止继续刷行情、写长进度、替成员取数。

### 3.2 执行预算（成员级铁律，防轮次耗尽）
- MCP/数据层取数合计 **≤4 次**（能批量就批量，只取本轮真正需要的）；
- 日K `limit` ≤250，更长历史改用 `period=week` / `month`；
- WebSearch ≤1 次且仅限非结构化资讯（行情/财务/资金禁用它替代结构化源）；
- 取数结束**立即写报告并回传**，写报告过程中禁止再开任何工具；
- 报告目标 **800–1500 字**；回合吃紧时保留「一句话判断 + 关键数据表 + 框架要点 + 免责声明」，优先保证回传。

### 3.3 恢复纪律（防掉线）
成员因轮次上限中断时，**只发一条**固定恢复指令：

> 停止一切新查询与 WebSearch。基于任务说明里的共享快照 + 你已拿到的数据，立即写出精简完整报告（800–1500 字，框架环节点到即可），通过回传通道交回。禁止再开工具。

同一成员最多恢复 1 次；仍失败则在最终报告标注该席位「缺席/执行中断」，**禁止代写**。有效回传 ≥4 席且关键维度已覆盖即可开始汇编；有多少席位汇编多少，勿无限空转。

### 3.4 任务说明模板（主理人 → 成员的派单格式）
```
用户问题：{原话}
本轮研究维度：{该成员本轮负责的维度与边界}
数据通道状态：{已连接/未连接 + 对应工具优先级（见 skills/data-layer/README.md）}
共享快照（主理人已取，直接引用，禁止重复取同一标的）：{代码/现价/涨跌幅/PE(TTM)；没有则写「无，请自取」}
执行预算：取数 ≤4 次；日K limit≤250；取数结束立即写报告；报告 800–1500 字；写完必须回传，禁止边写边查
产出方式：完整 md 报告正文回传（正文即权威内容）；{仅当用户要求保存文件时追加}报告存盘路径：{工作空间}/deliverables/{模式}/{日期}/
{可选附加语境：特殊时间窗、用户仓位状态、风格偏好等}
```

### 3.5 团队与子任务命名规范
- 团队命名：圆桌 `stock-partner-roundtable`、漏斗 `investment-masters-roundtable`、对抗 `trading-<标的简称>`、A股日常 `a-share-<任务类型>`；
- 子任务命名（CRITICAL）：如平台使用 `name` 参数派单，**必须**同时传成员 Agent ID（kebab-case 英文，与 `experts/` 文件名一致），禁止省略、禁止中文名；
- 语言一致：所有输出使用与用户原始需求相同的语言。

## 四、渐进式加载（成本与质量的最佳平衡点）

**绝不把全部人格塞进单次 System Prompt**（50+ 份、数百 KB，会严重稀释注意力）。正确姿势：

1. 常驻：仅保留「场景 → 模式/人格/技能」路由表 + 公共纪律；
2. 命中场景后，才把对应模式卡 + 参与成员的 md 注入上下文；
3. WorkBuddy / Claude Code 用 skills 目录 + 子代理提示词天然支持；自研框架按 `single-deep-report.md` 末尾的骨架代码实现"技能目录表 → 模型声明需要 → 下轮注入"。
