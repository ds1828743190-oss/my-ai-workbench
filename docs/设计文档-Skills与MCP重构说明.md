## 二、去人格化的处理方式（机制保留，身份剥离）

| 原包元素 | 处理 |
|---|---|
| "你是市场技术分析师"等身份声明 | → 改为职能指令："职责：分析 XX"；多阶段写作时用"从 XX 视角看"，不写"我是 XX" |
| 拟人花名（涂一线/牛正阳/严控风…） | → 全部移除；多代理派单用**职能 ID**（`phase1-technical` 等 kebab-case 英文） |
| 角色的"对话式、有攻击性"表达 | → 保留为**评审立场要求**（多头/空头/激进/保守/中性是审阅视角，不是人格） |
| 并行纪律 / 对抗机制 / 产物标记 / 裁决规则 / 盈亏比要求 | → **全部保留**（这是原系统的工程价值所在） |
| 单代理环境执行 | → 新增"方案 A · 单代理顺序执行"：逐阶段"立场切换"并显式声明，替代多代理并行 |

## 三、两个工作流的分工

```
用户问题
 ├─ "研究报告类"（分析/估值/财报/快评/跟踪） → equity-research（16 交付物）
 ├─ "交易决策类"（该不该买/卖给多少/仓位）   → trading-analysis（五阶段 → BUY/SELL/HOLD）
 └─ 取数与工具 → data-layer + mcp-guide（两个工作流共用）
```
