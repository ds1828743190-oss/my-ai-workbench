## 二、架构解析：星型主理人 + 6 套预设流水线

与本系列其他包的对比：

| 包 | 架构 | 特征 |
|---|---|---|
| `研股股-专家移植包` | 单专家 | 一份深度报告，无成员协作 |
| `投研专家团-移植包` | 星型并行 | 主理人 + 6 子代理一次性并行 |
| `投资大师专家团-移植包` | 四阶段漏斗 | 19 位并行 → 风险官 → 组合经理，必出 BUY/SELL/HOLD |
| **本包（A股研究团队）** | **星型 + 可编排流水线** | 6 套**预置 Workflow**，每套的串并行结构不同，主理人按问法自动选路 |

核心机制是**"先判类型，再选编排"**——不是所有问题都跑同一套流程：

```
用户提问
   │
   ├─ 综合性问题（"宁德时代能不能买" / "AI vs 新能源"）
   │     → 主理人匹配 6 套 Workflow 之一，按该 Workflow 的 Phase 串并行执行
   │
   └─ 单一问题（"贵不贵" / "北向在买什么"）
         → 直接调单个成员，不走 Workflow
```

**6 套预设 Workflow 的编排结构**（移植时必须保留的语义）：

| # | Workflow | Phase 1（并行） | Phase 2 | Phase 3 |
|---|---|---|---|---|
| 1 | 个股深度研究 | 个股 + 估值 + 资金 | 风控（串行） | — |
| 2 | 每日市场策略 | 宏观 + 盘面 | 资金验证（串行） | — |
| 3 | 板块比较选方向 | 产业链 + 宏观 | 资金 → 估值（串行） | — |
| 4 | 持仓诊断 | 每只持仓 × (个股+估值+资金) 并行 | 风控汇总（串行） | — |
| 5 | 沿主线找标的 | 盘面锚定（串行） | 产业链展开（串行） | 估值 ∥ 资金（并行） |
| 6 | 宏观传导分析 | 宏观传导（串行） | 产业链展开（串行） | 估值 ∥ 资金（并行） |

**决定产出质量的 5 条铁律**（移植时必须保留语义）：

1. **主理人不代写**——古见远只做编排与汇编，任何专业结论（基本面/估值/资金/产业链/风险/盘面/宏观）必须由对应成员输出后才采信
2. **先建团队再派活**——任务开始必须先创建协作空间，再按 Phase 拉人；不允许主理人自己模拟成员发言
3. **并行 Phase 真并行**——同一 Phase 内成员互不可见，独立视角才有多角度交叉验证的价值；顺序调用等于后手偷看前手答案
4. **串行 Phase 必须等前序**——不允许跳过 Phase 1 直接做 Phase 2；前序结论要作为输入传给后序成员
5. **信息经主理人中转**——成员之间不直连，所有跨成员信息流在汇编层汇合

**固定收口结构**：任何 Workflow 完成，报告必须含 `TL;DR → 核心结论卡片 → 正文 → 行动清单（≥3 条，带触发条件/时间窗）→ 风险提示 & 关键观察指标 → 数据来源 & 成员产出索引 → 免责声明`，并落盘到 `deliverables/a-share/<报告类型>-<主题>-<YYYY-MM-DD>.md`。

## 三、三层架构（移植映射表）

| 层 | WorkBuddy 里的机制 | 对应文件 | 移植到你的工作台 |
|---|---|---|---|
| ① 人设层 | Expert 主提示词 + 子代理提示词 | `agents/*.md`（8 份） | 主编排人 → Supervisor System Prompt；7 位成员 → 7 个 Worker Agent 的 System Prompt |
| ② 技能层 | Skill 按需加载 | `skills/westock/`、`skills/neodata-financial-search/` | 数据层知识包 / 取数工具封装 |
| ③ 工具层 | MCP 连接器 / 代理端点 | `MCP-数据接入指南.md` + 脚本 | 配置 MCP Client 或换等价数据源 |

**为什么分层很关键**：8 份提示词合计约 76KB，其中主理人一份就 17KB。若全塞进单次 System Prompt，会严重稀释注意力。原设计里主理人提示词承载"席位表 + 6 套 Workflow 编排 + 报告模板"，成员提示词在 spawn 时才各自注入——**移植时保留这个"编排者常驻、成员按需注入"的模式**。

## 五、数据依赖：双数据源（westock 主 + neodata 备）

本团队规定数据必须**来自真实查询、禁止编造**，链路为：

1. **主链路**：`westock` 技能（腾讯自选股）—— 含 `westock-data`（已知标的查行情/财报/资金/技术指标/机构评级）与 `westock-tool`（按条件批量选股）两支；技能内附 4 份 references 字段/场景指南 + 4 个已打包的取数脚本（约 6.3MB）
2. **备链路**：`neodata-financial-search`（腾讯 NeoData）—— 自然语言金融数据召回，覆盖 A股/港股/美股/日股/韩股 + 指数/板块/基金/宏观/外汇/大宗商品 七大类
3. **兜底**：WebSearch 搜索公开信息（成员提示词中已写明，且需标注来源）

移植到你的工作台有三条路线：

1. **有凭据路线**：向数据服务商（腾讯自选股 / 腾讯 NeoData）申请独立 API 凭据，按脚本的请求结构直接对接
2. **连接器路线**：自建 MCP Client 接入 `westock-mcp` / `neodata` 连接器（需自己的账号授权）
3. **开源替代路线**：用 AKShare / Tushare / 东方财富 / 大智慧等替换，改写 SKILL.md 里的调用步骤即可——**8 份成员提示词的分析框架不依赖具体数据源**，只依赖"能拿到行情/财务/资金/新闻"

> 详细接入字段、鉴权机制与替代清单见同目录 **`MCP-数据接入指南.md`**。

## 六、不可移植部分（明确告知）

| 资产 | 原因 | 替代方案 |
|---|---|---|
| WorkBuddy 平台系统指令与团队编排运行时 | 平台运行配置，不在交付范围 | 按第四节自己搭编排（LangGraph / CrewAI / AutoGen） |
| `connect_cloud_service` 鉴权通道 | 绑定 WorkBuddy 账号体系，取 `tempToken` 后走代理端点 | 向数据服务商申请独立凭据，或换开源数据源 |
| westock / neodata 连接器的账号授权 | 授权绑账号，不可整包搬运 | 用自己的账号在目标平台重新授权 |
| 底层模型能力 | 平台托管 | 接入你选定的任意大模型 API |
| 头像 PNG（3MB） | 仅影响渲染观感 | 可保留，可替换，可删除 |

**安全检查结论**：全包已扫描，无硬编码密钥。`query.sh` / `query.py` 的 token 走外部注入或本地缓存文件（`SKILLS_DIR/.neodata_token`，12 小时有效期），可安全分享。

## 七、落地清单（建议顺序）

1. **先单测成员**：任取 3 份成员提示词（建议宏观策略师 / 资金行为分析师 / 风险诊断师，视角差异最大），各跑一次"分析某只股票"，确认输出真的长在各自的独特增量区，而非同质化
2. **再搭路由 + 单 Workflow**：先实现"问法 → Workflow/成员"的路由，再挑 **Workflow 1（个股深度研究）** 跑通——它是"三路并行 + 一路串行"的最简完整形态，覆盖了并行、串行、汇编三种原语
3. **补齐 6 套 Workflow**：注意 Workflow 5/6 是"串行 → 串行 → 并行"三段式，与 1-4 的结构不同，不要复用同一张图
4. **最后接数据层**：从一家数据源起步，把成员提示词里的"数据获取"步骤映射到真实工具调用；保留数据来源标注
5. **保留合规底线**：报告末尾的免责声明、"不编造数字"、数据来源可追溯这几条建议原样保留
