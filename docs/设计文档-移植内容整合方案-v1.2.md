## 一、资产盘点：21 个节点到底是什么

先把所有材料按"性质"归成五类——这是后面一切拆分决策的依据：

| 类                        | 内容                                                                                             | 节点                                                                                                                | 本质                                      |
| ------------------------ | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| **A. 外部专家系统移植包**（5 套）    | 研股股（单专家+16技能）、投研专家团（1+6 圆桌）、投资大师专家团（1+19+2 漏斗流水线）、A股研究团队（1+7 六套 Workflow）、交易分析团队（1+12 多空对抗流水线） | 4 份 README + 4 份 MCP 指南 + 3 个 zip + 3 份专家提示词文档（industry-strategist / stock-partner-lead / equity-research-expert） | **提示词资产 + 编排模式**，全部纯 Markdown，无凭据，可自由改裁 |

| **D. 自建工作技能**            | price-cert-expert 价格认证专家包                                                                      | 汇总包 03 目录                                                                                                         | 已在 `my-experts` 私有仓库，**不重复纳入本项目**       |

### 关键判断：为什么不能简单堆在一起

五个移植包（A 类）看着是五个系统，实际上是**同一台机器的五种组装方式**：

- 人格高度重叠：5 套包里都有"基本面分析师、情绪分析师、风险经理"（连名字都重复：严控风出现 2 次、莫慌言 2 次、涂一线 2 次、季本实 2 次）。全搬 = 同一个职能存 3~4 份提示词，维护时改一处漏三处。
- 编排思想不同但互补：星型圆桌（投研专家团）、四阶段漏斗（投资大师）、六套 Workflow 路由（A股团队）、多空对抗辩论（交易团队）、单专家渐进加载（研股股）——这是 **5 种可复用的"编排模式"**，而不是 5 个必须整体保留的系统。
- 数据层重复 4 份：每包一份 MCP-数据接入指南，内容 80% 相同（neodata/westock 鉴权 + AKShare 替代路线）。应收敛为**一套统一数据层**。

结论：**按"层"切，不按"包"搬**。把 5 个包拆成三类原料——人格提示词、编排模式、交付物技能——分别入库，去掉重复，补上我自己的核心层。

## 二、总体架构：一个仓库，四大板块

建议新建独立仓库（与放工作技能的 `my-experts` 平级），例如 `my-ai-workbench`。定位一句话：**以我固化的投资策略与提示词为宪法，以外部蒸馏的人格/编排/技能为智囊团，以演化层沉淀我个人风格的个人 AI 工作台操作系统**。

```
my-ai-workbench/
├── README.md                      ← 项目总览、安装、各环境用法
├── workbenches/                   板块一：个人工作台（核心层 · 跨平台最小可用）
│   ├── investment/                投资台（本项目的主线）
│   │   ├── prompt.md              ← 现有"个人投资工作台提示词"，原样入驻
│   │   ├── strategy/              股债利差定投策略（固化规则）、数据源交叉印证协议
│   │   ├── templates/             台账模板.xlsx（空表）、信号卡模板、交易记录模板
│   │   └── signals/               历期策略信号卡（脱敏快照，可选）
│   └── media/                     自媒体台
│       ├── prompt.md              ← 现有"自媒体工作台提示词"
│       └── templates/             账号定位一页纸、选题池、剪辑效率流、数据追踪表
├── investing-os/                  板块二：投资智能体系统（投资台的深度能力）
│   ├── experts/                   人格库（三类，每人一份独立 md，统一 frontmatter）
│   │   ├── masters/               流派人格：巴菲特/芒格/格雷厄姆/费雪/林奇/塔勒布…（源自投资大师专家团）
│   │   ├── roundtable/            圆桌人格：星望远/文衡价/钊审财/坤候底/磊追浪/洲四方（源自投研专家团）
│   │   └── analysts/              职能分析师：宏观/盘面/个股/估值/产业链/资金/风险/技术/情绪/多空（源自 A股团队+交易团队，去重后各留一份）
│   ├── workflows/                 编排模式库（4 种模板，而非 4 套系统）
│   │   ├── single-deep-report.md      单专家深度报告模式（源自研股股）
│   │   ├── roundtable-parallel.md     星型圆桌并行模式（源自投研专家团）
│   │   ├── funnel-pipeline.md         漏斗流水线模式（源自投资大师专家团）
│   │   └── debate-adversarial.md      多空对抗+三方风险裁决模式（源自交易分析团队）
│   └── skills/                    交付物与工具技能
│       ├── research-deliverables/     研股股 16 技能精选（见 §四取舍清单）
│       ├── data-layer/                统一数据层：一套开源适配（AKShare 优先）+ 数据源协议
│       └── md-to-html/                报告渲染管线（投研专家团的 render.py，零依赖可直接跑）
├── quant-tools/                   板块三：量化验证三件套（GPL-3.0 原样保留）
│   ├── report-replication/
│   ├── backtest-overfit/
│   └── strategy-tearsheet-report/
├── personal/                      板块四：演化层（个人风格沉淀，项目"活"的部分）
│   ├── distillations/             博主/大师观点蒸馏卡（格式见 §五）
│   └── strategy-candidates/       策略候选区（未转正的我的想法）
└── docs/                          移植指南归档（4 份 README + MCP 指南，溯源用）、演化规范

### 四大板块的定位与边界

| 板块                | 目标                                   | 适用范围                                            | 调用方式                                           | 边界（不做什么）                                 |
| ----------------- | ------------------------------------ | ----------------------------------------------- | ---------------------------------------------- | ---------------------------------------- |
| **workbenches/**  | 任何 AI（Claude/ChatGPT/手机）粘贴即用的最小可用工作台 | 跨平台、无文件系统环境也能跑                                  | 整段复制 prompt.md 到首条消息；WorkBuddy 内直接下指令（「今日简报」等） | 不含重资产（人格库/技能库），保持轻量，保证"一段提示词走天下"         |
| **investing-os/** | 投资台的深度能力：多视角分析、深度研报、决策辩论             | 有 Agent 编排能力的环境（WorkBuddy / Claude Code / 自研框架） | 渐进式加载：常驻路由表 → 命中场景后按需注入对应人格/Workflow/Skill     | 不做实时交易、不替代核心策略规则；数据源走统一 data-layer，不各自为政 |
| **quant-tools/**  | 策略与因子的本地验证：复现、过拟合审计、绩效报告             | 本地 Python 环境，离线可跑                               | 作为独立 Skill 被投资台或人工直接调用                         | 不依赖外部平台额度；GPL-3.0 许可原样保留，不改许可证           |
| **personal/**     | 我个人风格的沉淀与演化                          | 所有环境（纯文档）                                       | 蒸馏卡随时新增；每月复盘时从候选区向核心策略"提案"                     | **只放方法论与观点，不放个人档案/财务/健康数据**（红线）          |

板块间关系：`workbenches/investment` 是宪法与入口；`investing-os` 是它的"重武器库"——提示词里已写明"环境自适应"（有文件/连接器就用，没有就降级），所以轻环境只用板块一，重环境叠加板块二三；`personal` 横跨所有板块，负责让它们越用越像"我"。

## 三、investing-os 内部设计（本方案的技术核心）

### 3.1 人格库 experts/：三分类，去重，可插拔

五个包共 50+ 份人格提示词，按"人格性质"分三类入库，**同一职能只保留最强的一份**：

- **masters/ 流派人格**（来自投资大师专家团，全保留）：巴菲特、芒格、格雷厄姆、费雪、林奇（麦哲伦舵手）、塔勒布（黑天鹅之父）、木头姐、大空头、宏观之王、Dhandho、估值教父等 19 位。价值：每位是一套**经典投资流派的可执行框架**（Owner Earnings DCF、NCAV、PEG、反脆弱……），这是五个包里独一无二的资产。
- **roundtable/ 圆桌人格**（来自投研专家团，全保留）：星望远（产业趋势）、文衡价（估值）、钊审财（财报）、坤候底（逆向）、磊追浪（短线）、洲四方（信号）。价值：最"有人味"的一套——源自真实股民访谈，视角互补且自带表达风格，与你的自媒体台也能联动（人物口吻即内容风格）。
- **analysts/ 职能分析师**（A股团队 + 交易团队 + 投资大师包三方去重）：宏观策略、盘面解读、个股研究、估值定价、产业链、资金行为、风险诊断、技术面、新闻面、情绪面、多头研究员、空头研究员、交易员、组合经理——**按职能留一份**，优先保留 A股团队版本（方法论框架最新最全），交易团队独有的"多空研究员/交易员"补入。

统一格式：每份 md 头部保留 `name / displayName / profession / description` frontmatter（任何支持 skill/agent 路由的框架都能解析）；保留每人的「独特增量区」定义——这是多视角不同质化的根基。

**扩展点**：你想新增"我自己"的分析师人格（比如"红利定投纪律官"），仿照格式写一份 md 丢进对应目录即可，路由表加一行。

### 3.2 编排模式库 workflows/：4 种模板，按场景取用

把 5 套系统的编排思想抽象成 4 张"模式卡"，每张卡写清：结构图、铁律、最小可行实现（N 次 LLM 调用版）、适用场景：

| 模式                  | 结构                                   | 适用场景                        | 最小实现                    |
| ------------------- | ------------------------------------ | --------------------------- | ----------------------- |
| single-deep-report  | 单专家 + 16 技能按需加载                      | "给我一份某只票的深度研报"              | 主提示词常驻 + 触发词路由加载 SKILL  |
| roundtable-parallel | 6 人格并行 → 主理人汇编                       | "多视角看看这只票/这个市场"，分歧本身就是产出    | 6 次并发调用 + 汇编模板          |
| funnel-pipeline     | N 流派并行 → 风险官 → 组合经理，必出 BUY/SELL/HOLD | 用经典流派框架做系统筛选                | 选中 N 人格并发 → 串行喂风险/组合提示词 |
| debate-adversarial  | 四维并行 → 多空辩论 → 交易提案 → 三方风险裁决          | **重大决策专用**：要求结论经得起多空与风险三方质疑 | 4 并发 → 3 串行 → 3 并发+1 串行 |

**四条公共铁律**（从 5 份 README 提炼的共性，写进 workflows/README）：

1. 主理人不代写——专业结论必须由对应人格输出后才采信；
2. 该并行的必须并行——顺序调用等于偷看答案，多视角价值归零；
3. 阶段间原文传递——下游输入是上游完整产出，不是摘要；
4. 裁决不许和稀泥——Hold 不是默认项，必须给明确方向。

**日常使用建议**：常态分析走 A股团队式的"意图路由"（问法→单人格或 Workflow，写进投资台提示词的指令集扩展区）；重大调仓决策走 debate-adversarial；想学某个流派时单点调用 masters/ 里的人格对话。

### 3.3 技能层 skills/：精选，不全搬

- **research-deliverables/**（研股股 16 技能，建议保留 8 个高频）：company-tearsheet、morning-note、initiating-coverage、earnings-analysis、comps-valuation、dcf-model-builder、event-scenario-analyzer、thesis-tracker。其余 8 个（earnings-preview、sector-overview、model-update、long-short-pitch、memo-builder、idea-generation、portfolio-risk、catalyst-calendar）作为"备选"放 docs 归档说明，需要时再启。理由：你的策略是低频定投，晨会/速览/财报/估值/事件/逻辑跟踪已覆盖全周期；长尾技能挂着不用只会稀释路由准确率。
- **data-layer/**（四份 MCP 指南收敛为一套）：统一封装 AKShare 为主（免费、覆盖广、纯本地）、Tushare/东财为备，接口契约参考 neodata `query.py` 的请求/响应结构；保留投资台已有的「数据源交叉印证协议」（两源一致才有效、主备降级、大智慧指数 PE 永久禁用等实战经验——**这是四份指南都没有的你的原创资产**）。
- **md-to-html/**：投研专家团的渲染管线（shell.html + render.py），零依赖 Python 脚本，直接搬。

### 3.4 工程核心：渐进式加载（必须保留的模式）

50+ 份人格 + 8 技能合计数百 KB，绝不能塞进单次 System Prompt。沿用各包共同验证过的模式：

- 常驻：投资台核心提示词（含策略宪法）+ 一张「场景 → 人格/Workflow/技能」路由表；
- 按需：命中场景后，才把对应人格 md / Workflow 卡 / SKILL.md 注入上下文；
- WorkBuddy / Claude Code 天然支持（skills 目录 + agent 提示词）；自研框架参考研股股移植指南方案 C 的伪代码（技能目录表 → 模型声明需要 → 下轮注入）。

**② 策略候选区**（`personal/strategy-candidates/`）——你自己的新想法、蒸馏后想试的方向，先放这里"冷藏"，附上验证标准（看什么数据、观察多久）。**每月复盘日**（投资台提示词已有"月度复盘"指令）对照实际执行记录，决定：转正进 strategy/、继续观察、还是放弃。这样核心策略既稳定又可演化——演化走流程，不靠冲动。

### 5.3 与灵感碎片的衔接（留在本地）

## 六、落地路径（分六个阶段，每步可验收）

**阶段 0 · 安全审查（半天）**

- 确认红线：台账真实数据、灵感碎片、文件传输助手记录、价格认证内部规范 → 不进仓库；
- 复核各移植包"无硬编码密钥"结论（原 README 已声明，建仓前再 grep 一遍 token/secret/Bearer）；
- GPL-3.0 三件套保留 LICENSE 与来源声明（ported_from pandaai）。

**阶段 1 · 建仓与核心层（半天）**

- 建目录结构 + README（项目定位、板块地图、安装与各环境用法、红线声明）；
- workbenches/ 入驻：两份提示词原样迁入，策略文档、协议、模板（台账做空表）归位。

**阶段 2 · 人格库蒸馏（1~2 天）**

- 解压 3 个 zip + 汇总包，按 §四清单抽取人格 md，统一 frontmatter；
- 去重裁决：同名职能对比留强（建议保留标准：方法论框架完整度 > 人设生动度 > 长度）；
- 写 experts/README（三分类索引 + 新增人格的格式规范）。

**阶段 3 · 编排模式卡（1 天）**

- 写 4 张模式卡 + workflows/README（四条公共铁律）；
- 每张卡附"最小可行实现"伪代码（并发 LLM 调用版，不依赖任何框架）。

**阶段 4 · 技能层（1~2 天）**

- research-deliverables 精选 8 个入驻；md-to-html 直接搬；
- data-layer：以 AKShare 写统一适配层，接口契约对齐 neodata query.py 的 query/响应结构；把数据源交叉印证协议作为该层的使用纪律文档。

**阶段 5 · 验证（1 天）**

- 单测：取 3 个风格差异最大的人格（建议 黑天鹅之父 / 坤候底 / 磊追浪），各跑一次同一只股票，确认输出真的不同质化；
- 链路：跑通一条 roundtable-parallel（6 并发 + 汇编）和一条 debate-adversarial；
- 核心回归：确认任何模式下，最终建议都必须回到股债利差区间规则复核（宪法优先）。

**阶段 6 · 发布与演化（持续）**

- 推 GitHub（建议 Private 起步，与 my-experts 同策略；README 写清 GPL 组件的许可说明）；
- 演化机制开始运转：蒸馏卡随时记、候选区每月复盘、新人格随时插拔。

## 八、边界声明（与既有仓库的分工）

- **本仓库（my-ai-workbench）**：投资 + 自媒体两条个人工作主线，含蒸馏的外部专家能力。
- **my-experts（已有）**：通用工作技能包（价格认证等），保持独立，本项目不重复收录；两个仓库共用同一套 SKILL.md/frontmatter 格式规范，日后可互相搬家。
- **本地独有（任何仓库都不放）**：个人档案、灵感碎片原文、台账真实数据、价格认证内部规范——延续既定红线。

## 附：方案决策的四个设计原则（日后扩容时回来看）

1. **核心轻，外重重**：板块一必须永远轻到"一段提示词走天下"；重资产全部沉到板块二三，按需加载。
2. **按层切，不按包搬**：任何新来的外部专家包，先拆成"人格/编排/技能"三类原料再入库，不允许整包塞进仓库。
3. **宪法优先**：所有智能体的产出最终都要接受固化策略规则的复核；演化走"蒸馏卡→候选区→月度复盘→转正"的流程，不改"策略不自由发挥"的根本纪律。
4. **诚实降级**：数据取不到就标注降级，绝不编造——这是所有移植包共同的合规底线，也是你数据源协议里已有的实战原则，全项目统一继承。
